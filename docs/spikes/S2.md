## 2. 실측 메모 (P02 T2·T6, P10a, SECURITY §2.1 Claude native 열 입력)

- **plan 모드는 정책이지 경계가 아니다**: `permissionMode:'plan'`에서 모델은 (1) `Write`로 `~/.claude/plans/<slug>.md` 계획 파일을 썼고 — 이 Write는 **canUseTool을 거치지 않았다**(plan 파일 경로는 Claude Code가 자동 허용) — (2) `ExitPlanMode` 도구를 호출해 canUseTool에 물었다. 1차 실측에서 앱이 `allow`를 돌려주자 CLI가 "User has approved your plan"을 넣고 **plan 모드를 벗어나** Edit(canUseTool에 물음)과 PowerShell `git diff --stat`(안전 명령, 물음 없음)을 실행해 README가 바뀌었다. 2차(`ExitPlanMode` deny)에서는 cwd 쓰기 0, 모델이 "플랜 모드 종료가 거부되어 … 실행하지 못했습니다"로 종료. → 앱 설계: **plan 모드 = canUseTool에서 `ExitPlanMode`를 거부(또는 사용자 확인)하는 정책 + `~/.claude/plans/` 쓰기는 허용 목록으로 인지**. SECURITY §2.1 Claude native "파일 시스템" 셀의 집행자 서술 "`permissionMode:plan`+`PreToolUse` 거부(정책만)"에 **ExitPlanMode 거부**를 추가해야 한다. 환경 불변 측면: 스파이크가 만든 plan 파일은 테스트 종료 시 삭제(`planFilesToRemove`).
- **acceptEdits 우회 목록(REQ-CAP-02 입력)**: `Read`, `Edit`가 canUseTool 0회로 실행됐다(README 변경). `Bash/PowerShell`·`Write`(새 파일)는 이 실험에서 호출되지 않아 미관찰 — Claude Code 규칙상 acceptEdits는 파일 편집 도구를 자동 허용하고 셸은 여전히 물으므로(문서 기준, 미실측) P02 T6 계약 테스트에서 셸 명령 포함 지시로 재실측.
- **PreToolUse 관찰 범위**: hook은 `tool_use_id`별로 모든 도구(Read·Edit·Write·ToolSearch·ExitPlanMode·PowerShell)를 관찰했고 권한 판정(canUseTool) **이전**에 호출된다(plan 모드에서 거부된 ExitPlanMode도 hook에 찍힘). → 감사 이벤트 소스로 사용 가능. hook 반환 `{}`는 판정에 영향 없음(`permissionDecision` 미사용).
- **interrupt**: receipt는 즉시(6ms), 턴 결과는 `error_during_execution`(`is_error:true`, `errors` 배열) — 어댑터는 interrupt 후 error 결과를 "사용자 중단"으로 분류해야 한다(`[Request interrupted by user]` user 메시지가 직전에 삽입됨). 중단 전 모델 출력은 `stream_event`로만 수신(includePartialMessages).
- **세션·fork**: `persistSession:true`면 `~/.claude/projects/<cwd 비영숫자→'-'>/<session>.jsonl`에 전사가 생기고 `listSessions({dir})`로 조회된다. `forkSession(id,{dir,upToMessageId})`는 즉시 새 id 반환·목록 반영(프로세스 기동 없이 파일 복제 — 추정). 스파이크 부산물인 임시 cwd 프로젝트 폴더는 테스트 종료 시 삭제. `persistSession:false`인 실행은 프로젝트 폴더를 만들지 않았다(테스트 후 `~/.claude/projects`에 `Temp-s2` 항목 0).
- **MCP(V13)**: `mcpServers:{}`+`strictMcpConfig:true`로 사용자 플러그인 MCP 서버가 **완전 배제**됐다(`mcp_servers:[]`). 단 플러그인(5)·스킬(89)·내장 도구 31개는 그대로 노출 → 스킬 노출 필터(U10)는 SDK 옵션이 아니라 앱 측 `settingSources`/`plugins` 제어 또는 프롬프트 수준에서 다뤄야 한다(S7·S9 입력). 기본 실행에서 플러그인 MCP가 `needs-auth`/`failed` 상태로 올라와 기동 시간에 영향.
- **인증**: API key env 없이 CLI OAuth 로그인으로 기동(`apiKeySource:"none"`). SDK 0.3.316 패키지에는 CLI가 동봉되지 않으므로(`cli.js` 없음) `pathToClaudeCodeExecutable`을 **감지된 CLI로 반드시 지정**(`CLAUDE_BIN` → `~/.local/bin/claude(.exe)` → PATH). ADR-0007 S3 입력.
- **elicitation(V18)**: 0.3.316 typings에 `Options.onElicitation(request: ElicitationRequest{serverName, message, mode:'form'|'url', url?, elicitationId?, requestedSchema?, title?, displayName?, description?})`과 hook 이벤트 `Elicitation`/`ElicitationResult`, 메시지 `SDKElicitationCompleteMessage`가 존재한다(타입 확인). **실호출은 MCP 서버가 elicitation을 보내야 하므로 미실측** → S9(c) 또는 P02 T2에서 in-process `createSdkMcpServer` 도구로 재현.
- **비용(C5)**: 실행당 `total_cost_usd` — deny 0.345, plan 0.488(5턴), acceptEdits 0.346, interrupt 0.0001, sessions/auth/mcp 각 약 0.235(1턴, 캐시 생성 11~12k 토큰). 사용자 설정·플러그인·스킬 목록이 시스템 프롬프트를 키워 1턴에도 캐시 읽기 19.5k.
