## 2. 데몬 런타임 비교(E3) → ADR-0005 D5 결정 **제안**

| 항목 | Electron `runAsNode`(`ELECTRON_RUN_AS_NODE=1 App.exe daemon.js`) | 동봉 Node(`resources/runtime/node.exe daemon.js`) |
|---|---|---|
| 실측 | pass — ABI 150(node 24.22.1); S6 데몬만 | pass — ABI 137(node 24.21.0); S6 데몬 + **S5 데몬(ws·HMAC) 기동** |
| 네이티브 모듈 조달 | `node_modules`(Electron 측) → `asarUnpack **/*.node`로 `app.asar.unpacked`에 패키지 전체 전개. N-API prebuild(napi 10)라 `electron-rebuild` **불필요**(`npmRebuild:false`) | `runtime-node-abi/`에 Node용으로 별도 `npm install` → `runtime/node_modules`. **같은 바이너리**(sha256 동일) → 리빌드 **불필요** |
| 설치 크기 | 추가 0(네이티브 모듈 37MB는 양쪽 공통) | node.exe 93.6MB + Node ABI 모듈 90MB(prebuild 8플랫폼·pdb 포함) → 설치 파일 +18MB·디스크 +89MB(모듈 분); 플랫폼별 정리·pdb 제거로 축소 가능 |
| 보안 함의 | fuse `runAsNode:true` 필요 → **서명된 앱 실행 파일이 범용 Node 인터프리터로 동작**: 로컬의 어떤 프로세스든 `ELECTRON_RUN_AS_NODE=1 App.exe <script>`로 앱 신원(서명·Defender 평판·방화벽 규칙)을 빌려 임의 코드 실행 가능. Electron 보안 가이드는 제품에서 이 fuse를 끄도록 권고 | fuse `runAsNode:false`로 잠글 수 있음. node.exe는 별도 실행 파일이라 앱 서명을 빌리지 않음(단, 설치 폴더 안에 사용자 권한으로 실행 가능한 범용 인터프리터가 하나 더 생김 — 서명·무결성 검증은 릴리스 파이프라인 과제) |
| 런타임 일치 | Electron 업그레이드 시 Node도 함께 바뀜(한 버전만 관리) | Node 버전을 별도로 고정·갱신(보안 패치 2중 관리). 스파이크는 실행 중 node를 복사했고 제품은 고정 바이너리를 내려받아야 함 |
| 의존성 로드 | asar 안의 JS(`ws` 등)는 `ELECTRON_RUN_AS_NODE`에서 asar 로더 없이 접근 불가 → 데몬 의존성을 unpack해야 함(미실측) | 일반 `node_modules` 해석 그대로(S5 데몬이 `runtime/node_modules/ws`를 로드함) |
| 패키징 함정 | 없음(실측) | electron-builder가 extraResources 루트 `node_modules`를 무조건 제외 → 별도 항목 필수(§1 #4); 하위 폴더(`s5/`)는 `**/*` 필터로 포함 |
| 진단 | Electron 바이너리 특성(crashpad 등) 상속 | 순정 Node — `--inspect`·heap 도구 그대로 |

**제안(D5): 동봉 Node 채택.** 근거: (1) 두 방식 모두 리빌드 없이 **같은 바이너리**로 동작함이 확인돼 "ABI 리빌드 부담"이 결정 요인에서 빠졌고, (2) 남는 차이는 **fuse `runAsNode` 보안 함의**(동봉 Node만 끌 수 있음)·**의존성 로드 단순성**(S5 데몬이 그대로 동작)과 **크기 +18/+89MB**인데 SECURITY_MODEL이 데몬 토큰·키링을 전제하므로 앱 실행 파일을 범용 인터프리터로 남겨 두는 비용이 더 크다. 비용 쪽은 플랫폼별 prebuild만 남기면 줄어든다. **ADR-0005 D5 확정·TECH_STACK §4 갱신은 사용자 확인 후** 수행(자동 수정 금지). 대안(runAsNode 유지)을 고르면 fuse를 켠 채 출시한다는 결정을 SECURITY §7에 명시해야 한다.

## 3. CSP — 완화 필요 항목(정본 수정 **제안**, SECURITY_MODEL §7 한 줄)

변형 5종(완화 전부 / 하나씩 제거, 자체 인라인 스타일 제거 후)으로 분리 측정한 결과(§1 #5a~5e):

| 변형 | style `'unsafe-inline'` | font `data:` | worker `blob:` | Diff | 위반 총계(directive) |
|---|---|---|---|---|---|
| canonical | ✗ | ✗ | ✗ | **fail** | 110(style-attr·style-elem·font·worker) |
| monaco-min | ✓ | ✓ | ✓ | pass | **0** |
| monaco-style-only | ✓ | ✓ | ✗ | **fail** | 4(worker-src blob) |
| monaco-no-style | ✗ | ✓ | ✓ | pass(렌더 깨짐) | 88(style-elem·style-attr) |
| monaco-no-font | ✓ | ✗ | ✓ | pass(아이콘 깨짐) | 4(font-src data) |

→ **Diff 동작의 필수 완화는 `worker-src blob:` 1개**, 정상 렌더링까지 하려면 **3개 모두** 필요. 현 정본 → 제안:

```
현 정본: default-src 'self'; script-src 'self'; style-src 'self';                 img-src 'self' data:; font-src 'self';       worker-src 'self';       connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'
제안   : default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; worker-src 'self' blob:; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'
```

| 완화 | 이유(실측) | 위험·대안 |
|---|---|---|
| `style-src 'unsafe-inline'` | Monaco가 동적 `<style>` 요소와 `style` 속성을 쓴다(자체 인라인 스타일 제거 후에도 잔존 → Monaco 귀속). nonce/hash로는 동적 속성 스타일을 허용할 수 없음 | 스타일 주입 XSS 완화가 약해짐. `script-src 'self'` 유지로 스크립트 주입은 여전히 차단. 대안(ESM 빌드 + CSS 추출)은 미실측 |
| `font-src data:` | codicon 아이콘 폰트가 `data:` URL | 위험 낮음. 폰트를 `app://`로 서빙하도록 번들을 가공하면 제거 가능(미실측) |
| `worker-src blob:` | Monaco 0.57 AMD min 빌드는 **`MonacoEnvironment.getWorker` 콜백을 호출하지 않고** 항상 `blob:app://bundle/<uuid>` 워커 2개를 만든다(Worker 생성 계측: 모든 변형에서 생성 URL이 blob:, 직접 생성한 app:// URL은 관찰되지 않음). blob 차단 시 워커 error 이벤트·Diff 미준비 | blob 워커는 같은 origin 스크립트만 실행 가능(`script-src 'self'`로 소스는 제한).
