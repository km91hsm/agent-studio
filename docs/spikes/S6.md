## 3. CSP — 완화 필요 항목(정본 수정 **제안**, SECURITY_MODEL §7 한 줄)

실측(§1 #5a~5c)으로 좁힌 최소 완화 3항목. 현 정본 → 제안:

```
현 정본: default-src 'self'; script-src 'self'; style-src 'self';                 img-src 'self' data:; font-src 'self';       worker-src 'self';       connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'
제안   : default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; worker-src 'self' blob:; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'
```

| 완화 | 이유(실측) | 위험·대안 |
|---|---|---|
| `style-src 'unsafe-inline'` | Monaco가 동적 `<style>`(elem 8건)과 `style` 속성(attr 24건)을 쓴다. nonce/hash로는 동적 속성 스타일을 허용할 수 없음 | 스타일 주입 XSS 완화가 약해짐. `script-src 'self'` 유지로 스크립트 주입은 여전히 차단. 대안(ESM 빌드 + CSS 추출)은 미실측 |
| `font-src data:` | codicon 아이콘 폰트가 `data:` URL(4건) | 폰트 데이터 주입 위험은 낮음. Monaco 폰트를 `app://`로 서빙하도록 번들을 가공하면 제거 가능(미실측) |
| `worker-src blob:` | `getWorkerUrl`·`getWorker` 어느 경로든 blob 워커 생성(4건) | blob 워커는 같은 origin 스크립트만 실행 가능(`script-src 'self'`로 소스는 제한). ESM 빌드의 `new Worker(new URL(...))` 경로는 미실측 |

**불필요한 완화**: `'unsafe-eval'`(동작함), `app:` 전용 directive(standard scheme이라 `'self'`로 서빙됨 — 정본 설계 그대로 확인). 정본 수정은 **제안**이며 AC-P08a-2에서 실제 UI 번들로 재검증한다. 변형 문자열은 `main.js`의 `CSP_VARIANTS`(측정용)에만 있고 정본 문자열 `CSP_CANONICAL`은 하나만 유지했다.
