## 3. 실측 메모

- **1차 설계 결함과 교정**: MASTER 그대로 `../outside.txt`와 `curl`(127.0.0.1)로 시작했더니 8행 전부 `bypassed`. 원인은 (1) 임시 cwd의 부모가 `%TEMP%`이고 Codex workspaceWrite가 TEMP를 기본 쓰기 허용 루트로 포함(`excludeTmpdirEnvVar` 기본 false), (2) loopback 허용. "외부"를 측정하려면 대상이 TEMP 밖이어야 하므로 영역을 `fs_outside`(저장소 안 git-ignored `.tmp/`) / `fs_tmp_parent` / `network`(loopback) / `network_external`로 나눴다(ledger Ruling).
- **on-request에서의 "승인 요청"은 두 종류**: (a) 샌드박스가 먼저 거부(exit 1)하고 모델이 같은 명령을 승인 요청으로 재시도 — `fs_outside`·`network_external` 전부, (b) 샌드박스 거부 없이 모델이 **자발적으로** 묻는 경우 — `fs_tmp_parent` elevated/on-request 1행. (b)는 집행자가 아니라 모델 판단이므로 보장 수준 근거로 쓰지 않는다(같은 영역의 never 행이 bypassed인 것이 집행자 부재의 증거). → **격리 판정은 `approvalPolicy:"never"` 행으로 한다**(승인 경로를 끈 상태의 샌드박스 단독 동작).
- **S1c 2×2와의 관계**: S1c(`writableRoots:[]`)의 외부 경로·네트워크 "승인 요청"은 (a)(b)가 섞여 있었다. S4의 never 행이 집행자 존재를 확정한다: 외부 경로·외부 호스트 = 샌드박스 차단(ENFORCED), TEMP·loopback = 집행자 없음.
- **unelevated 변형**: `-c windows.sandbox="unelevated"`를 app-server 기동 인자로 넘겼고 거부되지 않았으나 적용 여부를 돌려주는 API가 없다(`windowsSandbox/readiness`는 `ready`만). V29는 "elevated 기본값에서 차단 실측 확인"으로 해소하고, unelevated 동일성은 **추정**(S6 설치물에서 비관리자 계정 실측으로 보강).
- **Claude native**: `Write`(파일)·`PowerShell`(loopback curl) 모두 canUseTool allow면 즉시 효과. deny면 모델이 "정책 거부"를 그대로 보고하고 종료. SECURITY §2.1 Claude native 열의 POLICY_ONLY/DETECTED 값을 **실측으로 확정**.
- **효과 판정은 직접 관찰**: 파일 존재(`existsSync`), 수신 서버 hit 목록, `curl -w %{http_code}` 출력(`000` = 실패) — 모델 보고나 종료 코드에 의존하지 않는다(S1c 리뷰 #5 반영).
- **정리**: 테스트가 만든 `.tmp/` 폴더·TEMP 상위 파일은 `afterAll`에서 삭제. 비정상 종료 시 잔존 가능(수동 정리 대상 경로: `spikes/s4-isolation/.tmp/`, `%TEMP%\outside-*.txt`).
