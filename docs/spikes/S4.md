## 3. 실측 메모

- **1차 설계 결함과 교정**: MASTER 그대로 `../outside.txt`와 `curl`(127.0.0.1)로 시작했더니 8행 전부 `bypassed`. 원인은 (1) 임시 cwd의 부모가 `%TEMP%`이고 Codex workspaceWrite가 TEMP를 기본 쓰기 허용 루트로 포함(`excludeTmpdirEnvVar` 기본 false), (2) loopback 허용. "외부"를 측정하려면 대상이 TEMP 밖이어야 하므로 영역을 `fs_outside`(저장소 안 git-ignored `.tmp/`) / `fs_tmp_parent` / `network`(loopback) / `network_external`로 나눴다(ledger Ruling).
- **on-request에서의 "승인 요청"은 두 종류**: (a) 샌드박스가 먼저 거부(exit 1)하고 모델이 같은 명령을 승인 요청으로 재시도 — `fs_outside`·`network_external` 전부, (b) 샌드박스 거부 없이 모델이 **자발적으로** 묻는 경우 — `fs_tmp_parent` on-request 1행(3차 elevated, 4차 unelevated — 실행마다 다름). (b)는 집행자가 아니라 모델 판단이므로 보장 수준 근거로 쓰지 않는다(같은 영역의 never 행이 bypassed인 것이 집행자 부재의 증거). → **격리 판정은 `approvalPolicy:"never"` 행으로 한다**(승인 경로를 끈 상태의 샌드박스 단독 동작).
- **S1c 2×2와의 관계**: S1c(`writableRoots:[]`)의 외부 경로·네트워크 "승인 요청"은 (a)(b)가 섞여 있었다. S4의 never 행이 집행자 존재를 확정한다: 외부 경로·외부 호스트 = 샌드박스 차단(ENFORCED), TEMP·loopback = 집행자 없음.
- **unelevated 변형**: `-c windows.sandbox="unelevated"`를 app-server 기동 인자로 넘겼고 거부되지 않았으나 적용 여부를 돌려주는 API가 없다(`windowsSandbox/readiness`는 `ready`만). 행에 `variantApplied:"unverified"`를 기록하고 보장값 산출에서 제외했다. V29는 "elevated 기본값에서 차단 실측 확인"으로 해소하고, unelevated는 **미검증**(S6 설치물에서 비관리자 계정 실측으로 보강 예정, 그때까지 동등성 주장 없음).
- **Claude native**: `Write`(파일)·`PowerShell`(loopback curl) 모두 canUseTool allow면 즉시 효과. deny면 모델이 "정책 거부"를 그대로 보고하고 종료. SECURITY §2.1 Claude native 열의 POLICY_ONLY/DETECTED 값을 **실측으로 확정**.
- **효과 판정은 직접 관찰**: 파일 존재(`existsSync`), 수신 서버 hit 목록, 외부 HTTP는 **전체 명령 문자열에 호스트 + 전체 출력에 `000`이 아닌 상태 코드**(`externalHttpEffect`; 3차까지는 앞 100자로 잘린 명령에서 호스트를 찾아 긴 명령이면 응답을 받아도 `effect=false`가 될 수 있었다 — 리뷰 #1, 4차에서 교정). 모델 보고나 종료 코드에 의존하지 않는다. **차단 원인 대조**: 샌드박스 밖(테스트 프로세스)에서 같은 curl → `200`(`externalControl.reachableOutsideSandbox=true`) → 샌드박스 안 `000`/exit 1은 네트워크 차단이다.
- **정리**: 실행마다 `spikes/s4-isolation/.tmp/run-<pid>-<ts>/` 고유 하위 폴더를 만들고 `afterAll`에서 **그 하위와 자신이 만든 TEMP 상위 파일만** 삭제한다(3차까지는 `.tmp/` 전체를 지워 다른 파일을 지울 수 있었다 — 리뷰 #2). 비정상 종료 시 잔존 가능(수동 정리 대상: `spikes/s4-isolation/.tmp/run-*/`, `%TEMP%\outside-*.txt`).
- **픽스처 마스킹 보강(리뷰 #6)**: Claude 녹화의 `session_id`(UUID)와 이중 JSON 인코딩(4중 백슬래시) 홈 경로가 마스킹되지 않았다 → `mask.ts`에 세 규칙 추가(session id 전역 치환, 4중 백슬래시 홈 경로, 스트리밍 델타가 사용자명을 토큰 경계에서 자른 조각까지 덮는 `Users\<세그먼트>` 치환), `scripts/remask_fixtures.ts`로 기존 S2·S4 픽스처 13개 재마스킹(`--check` 0건, 사용자명 조각 grep 0건). **사용자 보고**: 커밋 `55da1b2`(S4)와 S2 커밋들의 공개 이력에는 session id·4중 백슬래시 경로가 남아 있다(사용자명 포함 경로 1건) — 8c1de76 건과 함께 force-push 여부 결정 필요.
