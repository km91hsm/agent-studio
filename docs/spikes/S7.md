- 모든 실험은 소형 버그 시나리오이며 4회 반복은 추출기 수정 때문이지 설계된 반복 측정이 아니다(결과는 4회 모두 같은 방향). 확정은 "행위 동등 + 결정 원칙"의 결합이고 통계적 결론이 아니다.
- 시그니처는 **절차** 신호다: 경쟁 스킬(tdd, diagnosing-bugs)의 실행도 주도 스킬 시그니처에 일치한다(`signatures.test.ts`에 음성 사례로 고정). 정체는 Skill 블록/주입/SKILL.md 읽기로만 판정한다. frontend-design·brainstorming·writing-skills의 원문 핵심 단계(계획·비평, 질문·승인, baseline)는 도구 관찰값에 없어 시그니처만으로 LOAD_OBSERVED를 줄 수 없다(각 JSON `note`).
- Claude 실행의 `permissionMode=acceptEdits` + `canUseTool` 전부 허용, Codex `approvalPolicy=never` + `workspaceWrite{writableRoots:[임시 저장소]}` — 승인 요청 0건 관찰. 승인 응답은 리뷰 #7대로 cwd 안일 때만 accept 하도록 고쳤으나 실측에서는 발동하지 않았다.
- 1~3차 관찰값·녹화는 4차로 덮어썼다(1~3차 픽스처는 세션 스크래치에만 보관). 1차 Codex `writing-plans` 읽기는 1차 녹화 grep으로 확인했으나 그 녹화는 남아 있지 않다.
- 시그니처 v2의 `reviewed_by`는 Codex 리뷰(수정 후 수용)를 가리키지만 **수정 반영분 자체는 재검토되지 않았다**(스파이크당 리뷰 1회 규약) → P07.
- 설치 테스트 (a)는 이 PC의 `~/.codex/skills` 상태에 의존한다(다른 PC에서는 LIVE 건너뜀).
- Codex 비용은 app-server가 제공하지 않아 토큰만 기록(리뷰 #11).
