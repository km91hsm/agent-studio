값(경로·명령)은 기록하지 않았다 — `notify` 값은 Desktop 앱 런타임 경로를 담고 있어 형태(`array(2)`)와 동일 여부만 남긴다(리뷰 #4). hooks는 양쪽 null이라 "상속되지 않음"을 **관찰할 수 없었다**(사용자 홈에 hooks 설정이 없음) — 제품의 유효 설정 스냅숏(R18)은 hooks 유무를 그대로 열거하면 된다.

**V31 판정**: `-c mcp_servers.<name>=…` 오버라이드는 **추가**이며 config.toml의 `[mcp_servers.node_repl]`을 **제거하지 않는다**(안정화 스냅숏 집합 차이 = ∅, 4회 실행 모두). 따라서 공유 홈에서 `-c mcp_servers`는 allowlist 집행자가 될 수 없고 SECURITY §2.1 MCP 셀의 "기본(공유) POLICY_ONLY"가 맞다. **격리 옵션의 집행자는 분리 `CODEX_HOME`**(플러그인·MCP·스킬 0, notify null)이며, 그 위에 `-c mcp_servers`로 앱 서버만 추가하면 조건부 ENFORCED(allowlist) 서술이 성립한다 — 단 분리 홈은 로그인이 없으므로 제품은 `auth.json`을 복사하거나 로그인 흐름(`account/login/start`)을 다시 밟아야 한다(미실측, P02 T2 입력). → P00 게이트에서 §2.1 MCP 셀 갱신 적용(P00_GATE.md §3).

**주의(LIVE 1·2차 교훈)**: `mcpServerStatus/list`는 initialize 직후 호출하면 비동기 등록 중인 원격 서버(codex-security, openai-api-*)가 빠질 수 있다 — 1차는 8개 유지, 2차는 원격 3개 부재로 "제거됨"처럼 보였다. 3차부터 이름 집합이 3회 연속 같을 때까지 폴링(4차: 공유 4회/7.1s, 오버라이드 3회/4.8s)한 뒤 비교한다. 제품의 "유효 설정 스냅숏"(R18)도 같은 안정화가 필요하다. Claude 쪽도 같은 변동이 있다: 기본 세션 `mcp_servers`가 3차 8개 → 4차 13개(claude.ai 커넥터 5개 추가 노출, 상태 pending/needs-auth)로 바뀌었다 — 사용자 환경 공유 시 스냅숏은 실행마다 달라질 수 있다.
