## 2. (g) 공유 vs 분리 `CODEX_HOME` 비교 + V31

| 항목 | 공유(사용자 홈) | 공유 + `-c mcp_servers.s9_probe` | 분리(빈 임시 홈) |
|---|---|---|---|
| `initialize` | ok(codexHome=홈) | ok | ok(codexHome=임시) — **로그인 없이도 initialize·목록 조회 가능** |
| `skills/list` | 21: user 8(C4 설치본) + 플러그인 8(computer-use, documents, pdf, presentations, spreadsheets×2, template-creator, visualize) + system 5 | 21 | **5(system만)**: imagegen, openai-docs, review-agent, skill-creator, skill-installer |
| `plugin/installed` | 25 installed(openai-bundled 6 + openai-primary-runtime 5 + …) | 25 | 0 |
| `mcpServerStatus/list`(안정화) | 7: codex-security, codex_app, codex_apps(410 tools), cua_repl(3), **node_repl**(config.toml), openai-api-credit-promo, openai-api-key-local-confirmation | **8 = 7 + s9_probe** | 0 |
| `config/read` layers | sessionFlags + user(`<home>\.codex\config.toml`) + system(`C:\ProgramData\OpenAI\Codex\config.toml`, 빈 파일 해시) | 동일(sessionFlags 해시만 다름) | sessionFlags + user(임시 홈, 빈 해시) + system |
| `experimentalFeature/list` | 194 | 194 | 194(피처 플래그는 바이너리 기본값) |

**V31 판정**: `-c mcp_servers.<name>=…` 오버라이드는 **추가**이며 config.toml의 `[mcp_servers.node_repl]`을 **제거하지 않는다**(안정화 스냅숏 집합 차이 = ∅). 따라서 공유 홈에서 `-c mcp_servers`는 allowlist 집행자가 될 수 없고 SECURITY §2.1 MCP 셀의 "기본(공유) POLICY_ONLY"가 맞다. **격리 옵션의 집행자는 분리 `CODEX_HOME`**(플러그인·MCP·스킬 0)이며, 그 위에 `-c mcp_servers`로 앱 서버만 추가하면 조건부 ENFORCED(allowlist) 서술이 성립한다 — 단 분리 홈은 로그인이 없으므로 제품은 `auth.json`을 복사하거나 로그인 흐름(`account/login/start`)을 다시 밟아야 한다(미실측, P02 T2 입력).

**주의(LIVE 1·2차 교훈)**: `mcpServerStatus/list`는 initialize 직후 호출하면 비동기 등록 중인 원격 서버(codex-security, openai-api-*)가 빠질 수 있다 — 1차는 8개 유지, 2차는 원격 3개 부재로 "제거됨"처럼 보였다. 3차부터 이름 집합이 3회 연속 같을 때까지 폴링(공유 4회/6.7s, 오버라이드 4회/11.8s)한 뒤 비교한다. 제품의 "유효 설정 스냅숏"(R18)도 같은 안정화가 필요하다.

## 6. 실측 메모

- **Desktop 앱 실행 중(정본 (e) 조건 미충족)**: `tasklist`에 `codex.exe`·`codex-computer-use-swift.exe`·`codex-code-mode-host.exe`·`codex-windows-sandbox-service.exe`. 사용자 앱을 종료하는 것은 세션 밖 부작용이라 하지 않았다. 영향: CAP-07 codex의 "`cua_repl` 도구 노출"은 앱이 띄운 MCP 서버일 가능성이 높고, 미실행 상태의 결과는 **미실측**. 재실행 절차: 앱 종료 → `AGENT_STUDIO_LIVE=1 npx vitest run spikes/s9-capabilities` → `raw.codexDesktopProcesses`가 `[]`인지 확인.
- **Claude `settingSources:[]`**: skills 89→19(내장 19: deep-research, design, dataviz, update-config, verify, debug, code-review, simplify, loop, schedule, claude-api, run, plugin-authoring …), plugins 5→3(builtin만), mcp 8→0. synced·사용자 스킬은 모두 'user' 소스에서 온다 → 앱이 사용자 환경을 공유하려면 settingSources 기본값, 격리하려면 `[]` + `plugins`/`skills` 옵션으로 선택 주입.
- **Claude `--chrome`**: `extraArgs {chrome:null}`가 그대로 전달돼 tools 31→53(+22 `mcp__claude-in-chrome__*`), mcp 서버 9개(+`claude-in-chrome`). 세션 자체는 정상 종료(`resultSubtype: success`). 확장이 실제로 연결됐는지는 조작하지 않아 모른다.
- **Codex documents 턴**: 승인 요청 0건(workspaceWrite 안 파일 생성·명령은 승인 없이 통과 — S1c와 일치), 모델은 python-docx 류가 아니라 플러그인 지침대로 zip을 직접 구성(commandExecution 8). 산출물 검증은 zip 매직 + `word/document.xml` 존재만(리뷰 관점 §10).

- **분리 `CODEX_HOME`**: `WARNING: proceeding, even though we could not create PATH aliases: Refusing to create helper binaries under temporary dir` — TEMP 아래 홈은 PATH alias 생성을 거부(동작에는 영향 없음). 제품의 격리 프로필 디렉터리는 TEMP 밖에 둔다.
- **녹화 크기**: 발견 응답(MCP 도구 스키마 410개 등)이 커서 줄당 30,000자 상한을 두었다(`…[truncated N chars]`). 판정에 쓴 값은 모두 raw 요약에 있다.
