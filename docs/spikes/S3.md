## 3. ADR-0007 재검토 조건 판정

재검토 조건: "공급자 약관이 CLI 로그인 재사용을 **명시적으로 금지**하거나 P00 S3 **실측에서 차단**될 때 → API key 기본으로 전환".

| 공급자 | 명시적 금지? | 실측 차단? | 판정 |
|---|---|---|---|
| OpenAI/Codex | **없음(로컬·오픈소스 앱은 명시적 허용, O1)**. 단 "commercial or hosted services"는 불허 | 없음 | **미발동** — 기본값(CLI 로그인 재사용) 유지. **조건부**: Agent Studio가 상업·호스팅 형태가 되면 그 시점에 SIWC(파트너 waitlist)로 전환 필요. SIWC 이전은 "권장" |
| Anthropic/Claude | **문자 그대로의 금지는 없음** — 금지 대상은 "제3자 개발자가 자기 앱에 Claude.ai 로그인을 제공·구독 자격증명을 사용자 대신 라우팅·토큰 수집/저장/중개"(A1·A5)이고, "end user가 **수정되지 않은** Claude Code 바이너리에 **자기** 구독으로 로그인"은 명시적으로 제한 대상이 아님(A2). Agent Studio 설계(토큰 비접촉, CLI 프로세스 자체 인증, 바이너리 무수정)는 A2 쪽 | 없음 | **미발동(조건부)** — 기본값 유지하되 아래 설계 제약을 ADR에 명문화하고 **공개 배포 전 Anthropic contact-sales 확인**을 게이트로 둔다. 제약 위반 또는 공급자 회신이 불허면 발동 |

Claude 측 "미발동"이 성립하는 **설계 제약(ADR-0007 개정 제안, 자동 수정하지 않음)**:
1. 앱은 Claude 자격증명·세션 토큰을 읽지·저장하지·중개하지 않는다(현재 S2 러너 구조 그대로 — `pathToClaudeCodeExecutable`로 사용자 설치 바이너리를 기동하고 인증은 CLI가 수행).
2. 로그인은 `claude` 바이너리의 Anthropic 자체 플로우(`claude /login`)로만 완료되며, 앱 UI는 "로그인 안내 → CLI 실행"만 제공하고 **"Claude.ai 로그인"을 제품 기능으로 광고하지 않는다**(A1·A5).
3. 바이너리 무수정, 내장 인증 방식(API key 포함) 제거·제한 금지(A4). 앱은 API key 모드를 항상 1급 선택지로 노출(ADR-0007 기존 결정과 일치).
4. UI에 약관 상태 안내 + "구독 한도·usage credits 차감 가능, 통지 없는 집행 가능"(A3·A6) 고지.
5. 공개 배포(다른 사용자에게 제공) 전 Anthropic contact-sales(Legal 페이지 안내 경로)로 허용 여부 확인 — ADR-0007 "공개 배포 전 사용·재배포 조건 확인 게이트"를 **릴리스 차단 조건**으로 승격. Codex 측은 상업·호스팅 전환 시 SIWC 파트너 절차.

→ **사용자 보고 사항**: ADR-0007은 "ACCEPTED" 유지, 위 5개 제약을 "결정" 절에 추가하고 재검토 조건에 "공개 배포 전 Anthropic 확인 미완료 / 상업·호스팅 전환"을 추가하는 개정을 **제안**한다(P00 종료 게이트에서 사용자 승인 후 적용).
