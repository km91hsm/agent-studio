# P01 — Shell·데몬 골격 + 상태·승인 계약 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (인라인, 이 세션이 구현자) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 각 Task 묶음 뒤에 Codex 리뷰(`codex exec -s read-only`) 1회, 마지막에 whole-branch 리뷰 1회.

**Goal:** 프로세스 3개(Shell·Renderer·데몬) 뼈대와 RPC·저널·Task 전이·승인 **계약(타입·스키마·단일 출처 파일)** 을 고정하고, 빈 Task가 `QUEUED→…→COMPLETED` 를 가짜 Gateway로 왕복하며 재접속 시 seq 누락·중복 0을 증명한다(AC-P01-1~7).

**Architecture:** npm workspaces 모노레포(`packages/protocol`=타입·JSON 단일 출처, `packages/core`=Journal·Scheduler·Broker·데몬 런처·RPC, `apps/daemon`·`apps/shell`·`apps/renderer`=엔트리). 저널(SQLite WAL, append-only)이 원본이고 투영은 파생·재구성 가능. Renderer는 데몬과 직접 통신하지 않고 main의 좁은 IPC 릴레이(`events.subscribe`/`rpc.read`/`rpc.write`)만 쓴다. P00 산출물 재사용: S5 데몬 락·HMAC 핸드셰이크·런처, S7 스키마 번들·diff.sh, S4 격리 경고 픽스처, S7 스킬 증거 등급 함수.

**Tech Stack:** TypeScript strict NodeNext / Node 24 / better-sqlite3 13.0.3 / ws 8 / `@napi-rs/keyring` 2.1 / Electron 45.2.1 / React 19 + Vite / Vitest 5. 기존 루트 `tsconfig.json`·`vitest.config.ts`·CI(windows+ubuntu) 확장.

**Spec:** `docs/planning/05_plan/PHASE_BREAKDOWN.md` §2 P01(T1~T12), `docs/planning/05_plan/ACCEPTANCE_CRITERIA.md` AC-P01-1~7, `docs/planning/01_architecture/SYSTEM_ARCHITECTURE.md` §1·§2·§4·§5·§6, `docs/planning/02_agents_state/DATABASE_SCHEMA.md`(이벤트 목록·투영·마이그레이션), `docs/planning/02_agents_state/PHASE_MANAGEMENT_DESIGN.md` §2(전이 규칙표), `docs/planning/02_agents_state/AGENT_INTEGRATION_DESIGN.md` §1(Gateway·공통 이벤트 10종), `docs/planning/04_security_test/SECURITY_MODEL.md` §2·§5·§7·§8, `docs/planning/03_skills/SKILL_EXECUTION_EVIDENCE_SPEC.md` §3·§4, `docs/planning/05_plan/MASTER_IMPLEMENTATION_PLAN.md` Global Constraints.

## Global Constraints

- Node `>=24.0.0 <25`, TypeScript만(Rust/.NET/Go 금지). 루트 `engines` 유지.
- Electron `webPreferences` 필수값: `contextIsolation:true, sandbox:true, nodeIntegration:false, nodeIntegrationInSubFrames:false, webviewTag:false, webSecurity:true, allowRunningInsecureContent:false, experimentalFeatures:false`, `devTools:isDev`.
- CSP 정본 문자열(SECURITY_MODEL §7, 바이트 일치): `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; worker-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'`. `app:` scheme은 `standard, secure`, `bypassCSP` 금지, `'unsafe-eval'` 금지.
- 데몬 RPC: 127.0.0.1, 토큰은 네트워크로 전송하지 않음(S5 HMAC 상호 증명), 프로토콜 버전 협상, PID·시작 시각·nonce 검증. Renderer는 토큰·포트·경로를 받지 않는다.
- 저널 append-only, 삭제·갱신 금지, 모든 전이는 저널 이벤트 1건과 1:1, 전이는 `transition()` 하나만 수행, fencing token 불일치는 거부 + `StaleWriterRejected`.
- 이벤트 타입 이름·투영 열은 DATABASE_SCHEMA 목록만 사용(새 타입 추가 금지 — 필요하면 기존 타입 payload로).
- 실행 제한 기본값: 승인 대기 15분 → `BLOCKED(approval_expired)`, lease TTL 90s / heartbeat 20s, 리뷰·수정 상한 3.
- 비밀 미저장: 토큰은 키링(`@napi-rs/keyring`) 참조만, 테스트·CI는 파일 토큰 저장소. 사용자 `~/.claude`·`~/.codex/*`·`AGENTS.md` 미수정, Codex는 `-c` 오버라이드 + `features.memories=false`.
- 커밋마다 push, 커밋 전 비밀 스캔(사용자명·호스트명·`ghp_`·`sk-ant`·`auth.json` 패턴 — 정의는 `scripts/mask_archive.py`와 동일), 커밋 메시지 끝 attribution 2줄. CI(windows+ubuntu)는 `npm ci → lint → test`를 통과해야 한다. LIVE(Electron·키링·codex CLI) 테스트는 `describe.skipIf(!process.env.AGENT_STUDIO_LIVE)` + win32 게이트.
- 수동 스킬 증거 프로토콜(AC-P10a-6): Task마다 주도 스킬 호출 블록 인용 + 산출물 경로를 `docs/agent-studio/P01/skill-evidence.md`에 기록.

## Review Focus

1. **락 파일은 있으나 데몬 PID가 재사용된 경우**(재부팅 후 다른 프로세스가 같은 PID): Shell은 접속을 시도하지 않고 stale로 판정해 새 데몬을 띄워야 한다 → Task 2 Step 3 `assessLock` 재사용 테스트(S5 `pid_reused`).
2. **재접속 직후 데몬이 이미 보낸 seq를 다시 보내는 경우**(구독 시작점 off-by-one): Renderer store는 중복을 버리고 `lastAppliedSeq`를 유지해야 한다 → Task 7 `applyBatch` 중복·역순 거부 테스트.
3. **lease 만료 뒤 옛 fencing token으로 전이 요청**: 거부 + `StaleWriterRejected` 기록, Task 상태 불변 → Task 4 Step 7.
4. **승인 요청이 15분 지나 만료된 뒤 사용자가 `approval.decide`를 호출**: 거부(`approval_expired`), Task는 `BLOCKED(approval_expired)` 유지 → Task 5 Step 7.
5. **Renderer가 preload 밖 경로로 데몬에 닿으려는 시도**(`fetch('http://127.0.0.1:<port>')`, `WebSocket`): CSP `connect-src 'none'`으로 실패해야 하고 preload는 세 함수만 노출 → Task 8 LIVE Step 5.
