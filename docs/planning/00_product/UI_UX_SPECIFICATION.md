| 메타 | 값 |
|---|---|

## 1. 설계 원칙

1. **설정은 한 번, 그 뒤엔 없이**: 첫 실행 시 설치된 CLI(claude/codex)와 **공급자별 인증 상태**를 감지해 보여준다. 인증 모드(기본 = 설치된 CLI 로그인 재사용)는 로그인 상태를 확인하고 약관 안내를 표시하며, API key로 전환한 공급자는 키 입력 경로를 보이고, **인증이 준비된 공급자만** 프로젝트 폴더 선택 후 즉시 대화 가능. 준비되지 않은 공급자는 비활성 + 설정 경로 안내(조용한 fallback 금지).
2. **두 가지 진실을 나란히**: 모든 작업 카드·채팅 턴에 "AI 보고"와 "검증된 사실(변경·테스트·스킬 증거)"을 분리 표시(REQ-WS-13).
3. **승인은 모달이 아니라 인박스**: 승인 요청은 전용 패널에 쌓이고, 요청마다 범위·위험·원문 명령·대상 경로를 보여준다. 사용자 부재 시에도 작업은 `WAITING_APPROVAL`로 정지만 한다.
4. **키보드 우선**: 모든 패널에 단축키와 명령 팔레트(`Ctrl/Cmd+K`). 접근성은 WAI-ARIA 역할·포커스 순서·스크린리더 레이블을 기본값으로.
5. **에이전트 구분 색·아이콘**: Claude/Codex 메시지와 도구 호출을 시각적으로 구분하되 색만으로 구분하지 않는다(아이콘+레이블).

## 2. 정보 구조

```
Home ─ Workspace(프로젝트별) ─ Project Planning ─ Sessions ─ Activity ─ Skills & MCP ─ Settings
       └ 좌: 탐색기 | 중: 채팅/편집기/Diff 탭 | 우: 타임라인·승인 인박스 | 하: 터미널·테스트 로그
```

## 3. 화면별 명세

### 3.1 Home (REQ-UI-01)
- 최근 프로젝트(마지막 활동 시각, 진행 중 Task 수, 대기 승인 수)
- 새 프로젝트(폴더 선택 → Git 감지 → 기술 스택 감지 결과 확인)
- 이어하기: 마지막 세션·Task를 한 줄 요약과 함께(Native Resume 가능/Checkpoint Restore만 가능 배지 구분)
- 실행 중 작업·승인 대기·오류 알림 카드. 데몬 연결 상태(연결됨/백그라운드 실행 중/중지) 표시
- 에이전트 상태 바: Claude 버전·로그인, Codex 버전·로그인, 약관 상태 안내(인증 모드)

### 3.3 Project Planning (REQ-UI-03)
- 요구사항 목록(ID·출처·상태), Phase 목록(상태 투영), Task 보드(QUEUED/진행/대기/완료/실패 열), 의존성 DAG(읽기 전용 그래프, 사이클 경고), 진행률(Task 완료 비율 + 검증된 비율), Acceptance Criteria 체크리스트, 검증 상태(증거 링크)
- 자동 생성 제안은 "제안" 탭에 Diff 형태로 표시 후 수락/편집(PHASE_MANAGEMENT_DESIGN §4)

### 3.4 Sessions (REQ-UI-04)
- 탭: Claude 세션 / Codex 세션. 출처: 공식 API(`listSessions()`, `thread/list`) + 앱 SessionIndex
- 검색·필터(프로젝트, 날짜, 연결된 Task), 세션 행 액션: **재개**(Native) / **분기**(Fork, Codex는 분기 턴 선택) / **읽기 전용 재생**(Replay) / **Checkpoint Restore**(세션 복원 불가 시만 활성)
- 대화 타임라인(공식 API로 읽은 메시지 + 앱 저널 이벤트 병합), handoff 기록

### 3.5 Activity (REQ-UI-05)
- 에이전트 실행 로그(AgentRun 단위), 도구 호출 목록, **Skills 실행 증거**(스킬·등급·증거 링크), 코드 변경(파일·해시), 테스트, 비용·사용량(Claude: USD 추정치 표시 + "추정" 배지, Codex: 토큰 5종, 금액은 단가표 입력 시만)

### 3.6 Skills & MCP (REQ-UI-06)
- 설치 상태(경로·커밋·해시·사본 일치), 호환성(Claude/Codex 열), 활성화 토글(프로젝트별), 라우팅 정책 표(Task 유형→주도 스킬), 사용자 전용·보류 배지, 깨진 참조 경고, 업데이트 검토(최신 커밋 비교, 실행은 승인), MCP 서버 목록·상태·권한

### 3.7 Settings (REQ-UI-07)
- 모델·에이전트(CLI 경로 감지, 인증 모드·약관 안내), 실행 모드 기본값, 보안·승인 정책 매트릭스(14행) + 권한 모드 옵트인(모든 공급자·OS·격리 조합에서 노출; 보장 수준 감소 항목 열거, 격리 미확인 조합은 경고 배지 + 활성 시 1회 확인 대화), 실행 제한(권장값·조정 범위 내 슬라이더), 로그·보존 기간·마스킹, 백업·복구(저널 내보내기/가져오기), 앱 업데이트 채널

## 4. 핵심 흐름 (REQ-GOAL-07)

1. 실행 → Home에서 프로젝트 선택(또는 새 프로젝트)
2. "이어하기" 또는 "새 대화" → Workspace
3. 자연어 지시 입력 → (Auto 모드) 작업 분석 결과·Phase 제안 카드 → 수락
4. Task 시작 시 스킬 선택 카드(주도 스킬·사유·증거 수집 방식) 표시
5. 실시간 스트리밍 + 타임라인 + 승인 인박스
6. 턴 종료 시 "AI 보고 vs 검증" 카드 → Diff 확인 → 사용자 승인(변경 수락/되돌리기)
7. Task 완료 → Checkpoint 저장 알림

## 5. 고빈도 이벤트 렌더링

- 데몬 → Renderer 구독은 저널 `seq` 범위 단위로 배치 전송(기본 50ms 코얼레싱), 텍스트 델타는 턴별 버퍼에 누적 후 `requestAnimationFrame`에 1회 반영.
- 타임라인·채팅·로그는 가상 스크롤 필수. 상태 라이브러리는 선택 사항이나 이벤트 스토어는 React 상태 바깥(불변 저널 캐시)에 두고 선택자만 구독.

## 6. 접근성·키보드

- 모든 액션에 단축키, 명령 팔레트에서 검색 가능. 포커스 트랩 없는 패널 전환(F6 순환).
- Monaco `accessibilitySupport: "on"` 옵션, xterm.js 스크린리더 모드 토글.
- 색 대비 WCAG AA, 애니메이션 감소 설정 존중.
